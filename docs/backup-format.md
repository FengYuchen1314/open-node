# 备份包 v1 格式

本页说明 Open Node 的 v1 备份清单、结构校验和命令行加密扩展。网页创建/下载、离线导入新目录
及首次启动复核现已接入；用法见[备份与恢复](backups.md)，官方依据见[备份计划](backup-plan.md)。

[实际快照与加密创建器](backup-runtime.md)会协调运行中的写入、复制数据库和状态文件并检查密钥依赖；
这些能力不属于本页通用格式校验器。仅运行 validate 不会执行恢复，仍不代表恢复就绪。

此格式与 MMWX 官方 ZIP、安装器的停服恢复包均不互通。验证器不会自动转换旧包、
执行数据库迁移或恢复文件；安装器的停服包继续使用自己的恢复流程。SQLite、
PostgreSQL 也不能借备份入口相互转换，本项目不提供旧 MMWX 迁移。

## 只读校验命令

主线从 `2a28103` 起提供 `open-node-backup validate`。安装包含这一入口的后端后，可执行：

```sh
open-node-backup validate ./backup.zip
open-node-backup validate ./backup.zip --json
```

从后端源码运行时，等价入口是 `python -m open_node.backup_cli`。命令只接受显式的
本地普通文件路径，不接受标准输入、URL、符号链接叶子、目录或特殊文件。当前依赖
POSIX 的 `O_NOFOLLOW`、`O_NONBLOCK` 和匿名临时文件能力；不具备这些能力时拒绝运行，
不会静默降低文件检查要求。

输入先以只读方式复制到 `/tmp` 下的匿名私有文件，再检查这一封闭副本。暂存文件
权限为 `0600`，成败都会关闭清理；需留出最多约 1 GiB + 16 MiB 的临时空间。程序
不写入源文件，也不加载 Open Node 配置、打开应用数据库、解压或恢复。文件系统
可能正常更新源文件的访问时间。

默认 Compose 的 `/tmp` tmpfs 只有 64 MiB。较大输入须在另行准备了足够私有暂存空间
的校验环境执行；命令不会自动扩大生产容器限制。1 GiB 是格式上限，不代表默认部署
能校验同样大小的包，其他临时文件也会占用可用空间。

人类输出为中文，JSON 仅含大小、数量、摘要和验证状态，不输出清单中的文件名、
源码声明或正文。退出码 `0` 表示结构与内容摘要检查通过，仍会明确显示恢复未就绪；
无效参数、坏包、不可读取或超限返回 `1`。`--help` 返回 `0`。复制和包校验分别有
30 秒操作间软期限，这不是能中断阻塞 I/O 的硬超时。

`validate` 入口不能创建系统备份或恢复实例。实际导入需显式调用独立的 `restore` 动作，
不应将格式验证报告解读为完整恢复报告。

## 加密已有包与只读解密校验

主线从 `a29345b` 起提供以下扩展；它不属于较早的 `2a28103` 格式切片。
它加密的是已经存在的 v1 ZIP，
不会遍历运行中的数据目录或替代一致快照。发布与验收状态见[交接记录](refactor-handoff.md)。

```sh
mkdir -m 0700 ./private
open-node-backup encrypt ./backup.zip --recipient age1... --output ./private/backup.zip.age
open-node-backup validate ./private/backup.zip.age --identity ./private/age-key.txt --json
```

`age1...` 是占位符，需换成实际的原生 X25519 公钥。备份加密私钥应独立保管，不放进备份包，
也不作为命令行参数或环境变量传入。这里的 `--identity` 指向本地私钥文件：必须属于
当前有效用户、权限为 `0400` 或 `0600`、只有一个硬链接、大小不超过 4096 字节。
允许官方 `age-keygen` 文件中的 ASCII 注释、空行和 CRLF，但只能有一条原生私钥。
符号链接叶子、额外密钥、口令模式、SSH、插件、PQ、多接收者及 armor 封装均不支持。
接收者、私钥和输出选项不能重复指定。

镜像内的实现固定为官方 [age v1.3.2](https://github.com/FiloSottile/age/releases/tag/v1.3.2)，
源码提交 `b74dce4cdbe35b5e5f66c06d9612b72f89028758`。构建时核对整个官方归档的 SHA-256，
只安装 `age` 和完整许可证；调用前再次核对当前架构 ELF 文件的摘要与权限，通过持有的
描述符执行，不依赖 PATH 查找。仅安装 Python 包不会自动安装这个可执行文件。
支持的二进制架构为 Linux amd64/arm64；真实运行验收仍以指定 VPS 的 amd64 为准。

外层采用受限的二进制 age v1：一个 X25519 stanza，168 字节头部，16 字节 nonce，
每 64 KiB 明文块附带 16 字节认证标签。密码学计算均由官方实现执行，项目只检查
封装范围并管理文件和进程。密文最多 1,090,785,464 字节，内部 ZIP 上限保持不变。
无效头部和不支持类型会在调用 age 前拒绝。

加密前先检查私有 ZIP 副本；解密时则必须等 age 完整退出成功，再通过独立 ZIP 校验，
才返回检查结果。损坏包可能在最终认证失败前产生部分明文，这些字节只在匿名私有
暂存文件里，失败即关闭，不导出到用户目录。子进程不继承应用环境，私钥只经只读
描述符传入，stderr 不对外转述；设置 core/file-size/CPU 限制，并有 30 秒进程期限。
超时会终止并回收子进程，但不承诺能强制结束内核中不可中断的磁盘 I/O。

复制、摘要与 ZIP 校验各有操作间软期限。匿名临时文件最多约需两个完整包的空间，
还要为最终密文输出另留空间。默认 `/tmp` 的 64 MiB 限制没有扩大；普通 ZIP 能检查
通过，不代表同一环境有足够空间再做加密。同步接口也不承诺外层异步任务取消后，
已运行的后台线程会随之立即停止。私钥字节可能留在 Python 堆中，不承诺内存擦除。

实际容器验收中，同一份约 40 MiB 的 ZIP 在 64 MiB tmpfs 下能只读检查，但加密时
临时空间用满并安全失败；独立 128 MiB 容器的加密与解密校验通过。这只是该测试包
的观测结果，不是通用容量配额，不能忽略其他进程的临时空间占用。

输出父目录必须已存在、属于当前用户且不允许组或其他用户写入；父目录叶子不能是
符号链接。密文先写入该目录中的随机私有暂存文件，重新核对大小和摘要并刷盘，再以
硬链接原子创建目标路径。已有文件、目录、链接或特殊文件一律不覆盖；不支持此发布
方式的文件系统会报错，不退回到可能覆盖旧文件的操作。最终文件权限为 `0600`。

目标路径创建后，若目录刷盘或终端输出失败，退出码 `1` 仍可能伴随一个完整的新密文
文件。命令不会回头删除这个公开目标名，以免误删并发替换的文件；重试仍拒绝覆盖，
应先检查现有文件。不可恢复的文件系统错误或进程被强制杀死也可能留下私有密文暂存。
这不是跨文件系统或断电情况下的事务回滚保证。

普通 `validate` 的 13 项 JSON 字段保持不变。加密操作和带私钥的校验另增加
`encryption`、`encrypted_size`、`encrypted_sha256`、`authenticated_decryption`。
最后一项只有完成私钥解密认证后才为真；单纯生成密文不会冒充已完成解密验证。
外层认证通过不证明发送者身份，所有数据库、库内密钥配对、来源、一致快照及恢复
状态仍未验证，`restoration_ready` 仍为 `false`。

## 归档范围

归档采用受限的 ZIP_STORED，不压缩。根目录必须有且只有一个 `manifest.json`，
其余成员与清单逐项对应，不接受清单外文件、目录条目或重复名称。

| 角色 | 包内路径 | `included` 声明需要的成员 |
| --- | --- | --- |
| `database` | SQLite 为 `data/open-node.db`；PostgreSQL 为 `database/postgres.dump` | 恰好一个与清单数据库类型匹配的制品；结构校验阶段不打开数据库或运行 `pg_restore` |
| `certificate_state` | `data/certificates/` 下的普通文件 | `vault.key`、`vault.initialized`；其他证书、ACME 账户和任务状态按清单保留 |
| `external_state` | `data/external-subscriptions/` | 恰好 `vault.key`、`vault.initialized` |
| `federation_state` | `data/federation/` | 恰好 `vault.key`、`vault.initialized`，与库内共享服务器 Token 密文配套 |
| `notification_state` | `data/notifications/` | 恰好 `telegram.key`、`telegram.initialized` |
| `agent_identity` | `secrets/agent-identity.seed` | 恰好这一项 |

SQLite sidecar 不在此布局内，不能把运行中的 `.db` 主文件直接当成独立快照。
PostgreSQL 成员必须是创建器生成并经 `pg_restore --list` 验证的 custom dump；裸数据目录、
SQL 文本和安装器包内单独取出的 `postgres.dump` 都不能冒充完整 v1 包。
证书树内合法的普通文件名不因恰好以 `.db-wal` 结尾或名为 `manifest.json` 而被删除。
它们仍受路径、文件数和总量限制。

这里只定义逻辑路径。包内内容不能指定主机目标目录、配置环境变量或执行命令。
远端 Agent 文件不在控制面归档内，部署设置及 TOTP 环境密钥也不自动进入包中。

## 清单约束

`manifest.json` 必须是严格 UTF-8 JSON 对象，根字段恰好如下。未知字段、重复键、
浮点数、非有限数值、布尔值冒充整数及隐式类型转换均会被拒绝。

| 字段 | v1 规则 |
| --- | --- |
| `format` | 固定为 `open-node-control-plane-backup` |
| `version` | 整数 `1` |
| `created_at` | 真实有效的 UTC 秒级日期，形如 `2026-08-31T09:00:00Z` |
| `source` | 必须包含 `git_revision`、`image_id`、`image_revision`；各项可为 `null` |
| `database` | 仅接受 `sqlite` + `standalone` 或 `postgresql` + `custom_dump`；`schema_fingerprint` 为 SHA-256 或 `null` |
| `coverage` | 必须包含 `certificates`、`external_subscriptions`、`federation`、`notifications`、`agent_identity` |
| `required_configuration` | 不重复的枚举数组，必须含 `deployment_settings`，可另含 `subscriber_totp_key` |
| `files` | 非空数组；每项恰好包含 `path`、`role`、`size`、`sha256` |

两种 Git revision 使用 40 位小写十六进制，同时存在时必须相同。`image_id` 使用
`sha256:` 加 64 位小写十六进制；其他 SHA-256 字段为 64 位小写十六进制。这些是
清单声明，不是对镜像、源码或数据库模式的认证。

`coverage` 各项只能为 `included`、`not_configured` 或 `unknown`。声明 `included`
需要满足上表的文件集合；另外两个状态不允许携带该角色文件。文件齐全仍不能证明
密钥正确或配对成功。未声明 `subscriber_totp_key` 也不能证明库内没有 TOTP 密钥依赖。
恢复入口拒绝任何仍为 `unknown` 的范围。早期内部 v1 草案如果没有 `federation` 字段，
会被当前严格解析器拒绝；不做就地补字段或旧包迁移。

路径必须是规范的相对 POSIX 路径和 NFC 文本。允许普通中文和其他合法 Unicode 字符，
拒绝绝对路径、空路径段、`.`、`..`、反斜线、冒号、路径段首尾空白或尾点，以及
控制字符、格式控制符、孤立代理项和行段分隔符。不做 URL 解码、路径修复或 Unicode
归一化；相同名称和文件与父目录冲突都被拒绝。

## ZIP 和资源边界

文件名标志只接受 ASCII 或明确标记的严格 UTF-8。v1 不接受 CP437 名称、压缩、
ZIP 自带加密、ZIP64、data descriptor、额外字段、注释、多卷、链接和特殊文件。
创建系统仅接受 DOS/Unix，版本仅接受 1.0/2.0。普通文件可采用 Unix 常规文件类型，
或 Python 默认的仅权限位表示；setuid、setgid、sticky 和目录等属性不被接受。

校验器先按原始字节检查 EOCD、中央目录、每个本地文件头和连续物理布局，再交给
标准库读取正文。实际条目数必须与声明一致，头部字段必须相符，归档不能有前缀、
空洞、重叠或尾部附加内容。正文中的 ZIP 签名或完整嵌套 ZIP 只是普通字节，不递归解包。

| 限制 | 上限 |
| --- | --- |
| 清单原始字节 | 1 MiB |
| 清单以外的文件数 | 4096 |
| 单文件及全部文件正文之和 | 各不超过 1 GiB，清单单独计限 |
| 包的实际长度 | 1 GiB + 16 MiB |
| 路径 / 单路径段 UTF-8 长度 | 1024 / 255 字节 |
| JSON 容器深度 | 12，根容器算 1 |
| JSON 节点 | 80000，按容器和值计数，不把对象键另算一个节点 |
| 每次底层读取 | 最多 64 KiB |

中央目录长度、累计读取字节数和 I/O 检查次数也有独立预算。校验过程在操作之间
检查 30 秒软期限；这不能中断已经阻塞的底层 I/O，网络流和不可信流实现不符合输入
合同。超限或损坏统一抛出安全错误，不附带成员名、文件内容或底层异常信息。

内部验证接口要求调用方持有已完成、私有且独占的可定位二进制流。它不写入、不关闭
调用方流，游标可能改变。结束时会复核同一对象的实际长度，但这不是锁，也不能证明
另一个写入者没有改过同尺寸内容。

## 内部生成接口

`write_backup_archive` 接受已经验证形状的清单模型、按包内逻辑名称给定的独立输入流，
以及空的私有暂存流。它不会遍历目录、根据清单打开主机文件、启动应用或生成数据库
快照。源流的稳定性和私有所有权仍由上层负责，目标含有任何原内容都会被拒绝。

生成器检查实际源长度和摘要，处理有界短读与短写，使用无压缩、无额外字段的固定
ZIP 配置。清单为 UTF-8、排序键的紧凑 JSON；ZIP 的 DOS 时间固定为 1980-01-01，
不表示原文件修改时间。关闭 ZIP 结构后，它会调用独立验证器复核完整制品，成功
返回同一种结果，不提高数据库、密钥或恢复状态。

失败可能留下部分暂存字节。调用方必须丢弃这些字节，不能发布、重用或解释为完整
备份；生成器不关闭调用方流。生成与复核各有独立的 30 秒操作间软期限。这个低层接口
本身仍不获取应用快照或发布网页制品；当前网页流程由上层快照创建器调用它，再执行
age 加密、权限检查、限时下载和撤销控制。命令行的外层加密不能替代该流程。

## 校验结果的含义

成功报告包含实际包大小、正文总量、文件数、清单摘要和 `checked_archive_sha256`。
后者按本次实际检查的物理顺序覆盖文件头、正文、中央目录和 EOCD，不能用来保证
一个后来被改写的原文件仍然相同。每个正文还会分别核对实际长度、CRC 和清单 SHA-256。

结果中只有 `structure_verified` 和 `content_hashes_verified` 为真。来源认证、
数据库、密钥配对、一致快照和恢复检查均为 `not_checked`，`restoration_ready`
固定为 `false`。单纯的空文件或错误密钥也可能通过结构检查，这不代表可恢复。

SHA-256 不能替代认证，攻击者可以重算整个清单。ZIP 内可能包含私钥、令牌和账户
状态；内部 ZIP 本身没有加密，不能直接作为公开下载制品。外层加密已通过专项、
4048 项完整后端、真实 1 GiB 包、工作树与精确 Git 镜像及候选四项 CI，并以
`a29345b` 发布到主线。当前源码已在此格式之上接入 SQLite/PostgreSQL 一致快照、
联邦状态依赖检查、网页权限和隔离恢复；单独运行本页的结构校验仍不会执行这些动作。
