# 应用内备份：官方依据与后续实施边界

状态：已实现 v1 清单解析、只读 ZIP 结构校验、内部生成器与中文命令行校验入口；
已以 `2a28103` 发布到主线，不属于站点文字提交 `f0ed515`。格式与校验边界见
[备份包 v1 格式](backup-format.md)。现有安装器在升级前生成停服整卷备份；
网页仍没有生成、下载或恢复备份的入口。
已验证的停服备份、隔离恢复流程不重做，用法见[部署说明](deployment.md)。

## 官方行为

主参考固定为 `tajiaoyezi/miaomiaowuX` 的
`c12ce653bc07fe30426b7dfcb85076974b7be0e0`，不随主分支静默变化。

- [路由注册](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/cmd/server/main.go#L422)
  提供管理员下载、上传恢复；初始化还另有无用户时可调用的恢复入口。
- [下载处理](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/handler/backup.go#L30)
  在 SQLite checkpoint/健康检查后打包 `data/`、`subscribes/`，先在内存完成 ZIP。
  新导出为普通 ZIP，旧加密包仅在导入时按原口令解密。
- 固定代码允许按管理员选择附带 PostgreSQL custom dump。2026-08-31 读取的
  [官方备份文档](https://miaomiaowux.com/docs/en/backup-restore/)仍描述 SQLite ZIP
  与 PostgreSQL 分开备份；两者并不完全一致，不能把文档当作该提交的执行结果。
- [恢复处理](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/handler/backup.go#L425)
  的 PostgreSQL 分支验证暂存库后切换配置；SQLite 分支直接替换当前目录文件。
  返回信息中的“正在重启”不能证明 SQLite 已切换到新库，实际重启只在
  `databaseSwitched` 为真时触发。
- [解压循环](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/handler/backup.go#L805)
  虽有路径检查和每文件临时替换，但没有限制总展开大小；请求体的 1 GiB 上限
  不等于解压后的资源上限，也不使多文件替换变成整体事务。
- [数据库备份 helper](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/storage/database_backup.go#L56)
  使用 SQLite Online Backup API、验证新快照并在失败时保留旧备份。上述下载
  handler 没有调用它；数据库一致性也不等于数据库与证书、密钥文件同时一致。

MMW 的远程抓取、上传和合并导入是另一条迁移流程，不能与整实例恢复合并成一个
“导入”动作。本项目也不因参考备份功能而接入许可证服务或新增付费门槛。

## 现有基础与缺口

`install.sh` 的 `backup_stopped_volume` 已覆盖：停服整卷归档、SQLite 完整性检查、
原配置和镜像身份、SHA-256 清单、空卷验证，以及完成后发布备份目录。
它是受控主机安装器的能力，不是允许 Web 进程获得 Docker socket 的理由。

完整控制面恢复不仅需要 SQLite，还需要证书 vault/ACME 状态、外部订阅密钥、
通知密钥及初始化标记、Agent 身份和匹配的环境配置。TOTP 加密密钥来自环境，
不能假定数据库或数据卷已包含它。自定义到卷外的目录必须显式识别；不能在
缺少关键文件时仍把包标为“完整可恢复”。远端 Agent 文件不在控制面备份范围内。

当前应用有库存、认证、证书等独立连接池，还有证书、访问同步、流量和通知四类
后台任务；HTTP 请求和 Agent 消息也可能写数据。目前没有统一的备份停写屏障。
仅执行 checkpoint、只阻止网页保存，或复制运行中的 `.db` 主文件都不足以证明
跨数据库和文件的一致性。

只拦写入请求的方法名也不够。管理员和订阅用户的 GET 鉴权会更新会话，临时订阅 GET
会增加访问计数，部分订阅 token 查询还会创建记录。Agent 已建立的 WebSocket 会继续
写心跳、流量和命令回执；备份协调需要按消息和操作计数，不能等整条长连接退出。
外部订阅抓取会先关数据库会话，等待线程中的 HTTPS 抓取，再重新写库，因而“当前
没有事务”不能证明操作已经结束。

下一阶段的停写协调须覆盖操作全生命周期和三个数据库连接池。进入备份时先暂停
新任务，允许已有证书任务收到 Agent 回执并完成清理；等线程、子进程、文件写入及
提交全部结束，再短暂封闭其余操作并复制私有快照。超时应返回忙碌并恢复接单，不
终止任务来制造成功结果。异步请求取消不等于其后台线程已经停止，通知 worker 的
有限等待也不能替代实际线程完成检查。

证书 `worker.lock` 是持有到 worker 退出、还可能传给子进程的生命周期锁，不能拿来
充当全局备份锁。多进程、启动迁移和管理员 CLI 也需要明确的实例所有权协议；仅在
一个请求里加 Python 锁不足以约束它们。这些仍是待实现的运行时协调，格式校验和
内部生成器都不承担这一职责。

安装器会在运行中的容器里调用 `open-node-admin create` 创建管理员；停写协议也须
覆盖这条受支持的独立进程写入，不能用禁止一切并行 CLI 的方式破坏新装流程。

### 持久化范围核对

下表是运行时的实际来源；包内逻辑路径另见 v1 格式。自定义目录需要显式映射，
不能从不可信清单取得主机路径后自动读取。

| 角色 | 当前来源 | 不能遗漏的内容 |
| --- | --- | --- |
| 控制面数据库 | Docker 默认 `/var/lib/open-node/open-node.db` | 整库，包括认证、会话、订阅、Probe、Agent 凭据及待办状态 |
| 证书与 ACME | Docker 默认 `/var/lib/open-node/certificates` | vault 密钥和初始化标记、账户、证书及私钥、未完成任务状态；不能把整个 jobs 目录当缓存丢弃 |
| 外部订阅密钥 | 默认数据库同目录的 `external-subscriptions/` | `vault.key`、`vault.initialized`，与库内 source/node/preview 密文配套 |
| 通知密钥 | 默认数据库同目录的 `notifications/` | `telegram.key`、`telegram.initialized`；禁用通知或清空 Token 不等于可以删除密钥依赖 |
| 控制面 Agent 签名身份 | `OPEN_NODE_AGENT_IDENTITY_FILE` 指定文件 | 原 32 字节 seed 与匹配配置，不是远端 Agent 的命令库或运行时文件 |

数据库 URL、上述自定义目录、`OPEN_NODE_SUBSCRIBER_TOTP_KEY`、Cookie/CORS、
ACME 和公网地址等设置，以及 Compose 的端口与代理信任配置，不能假定会随数据库
恢复。首期验证器只接受固定枚举的依赖声明，不导入任意环境变量。证书 webroot
绑定记录还含宿主路径、device/inode；保留记录不代表新主机上已经重新验证路径。

源码接点：[设置](../backend/app/open_node/core/config.py)、
[外部订阅目录推导](../backend/app/open_node/services/inventory.py)、
[通知目录推导](../backend/app/open_node/main.py)、
[证书 vault](../backend/app/open_node/services/certificate_vault.py)和
[Agent 身份读取](../backend/app/open_node/services/secure_channel.py)。

现有数据库采用建表、列检查与增量迁移，没有统一的数据库模式版本表。应用版本或
Agent manifest 的版本不能冒充数据库版本。SQLite 的 WAL/SHM/journal 也不能直接
当缓存丢弃；首期格式如只接受独立快照，应明确拒绝尚需 sidecar 的布局，现有停服
整卷归档则继续保持原格式和恢复流程，不做静默转换。

## 实施顺序

1. 版本化清单、只读归档校验、生成器和 CLI 已通过专项、完整后端、精确镜像及候选 CI。清单记录
   数据库布局、声明的源码/镜像身份、文件大小和摘要、配置/密钥依赖及范围。
   字节校验通过不证明这些声明与实际数据库、密钥或部署环境匹配。
2. 证明所有写入者与密钥/证书文件的一致快照边界。可以采用有界停写与事务协调，
   但必须覆盖所有连接池、后台任务及已在运行的请求；不支持的多进程或目录布局
   应明确拒绝。做不到时继续使用既有停服流程，不以不完整在线导出代替。
3. 管理员显式创建备份，生成私有且有大小/数量/时间限制的临时制品，验证全部成功
   才提供下载。下载同一个制品不重复执行创建；中断和失败不破坏上一个完整包。
4. 使用独立口令或接收者密钥加密；具体算法和格式必须采用成熟实现并有兼容测试。
   不用归档内自己的密钥加密自身，不把口令、私钥、备份正文或临时路径写入日志。
5. 首期恢复仍限停止服务后的独立空目录/空卷。在线覆盖正在使用的数据库、匿名
   初始化上传、远程 URL 抓取、PostgreSQL 迁移和自动异地上传另行设计，不预先
   放入界面成为无法兑现的操作。

## 恢复前的安全策略

第一阶段的只读验证器只检查格式、版本、资源边界和文件摘要，不创建应用连接池、
不启动后台任务，也不解包到现有数据目录。清单采用受限的 UTF-8 JSON：拒绝重复键、
未知字段、非有限数值、隐式类型转换及超过深度、大小和文件数上限的内容。文件角色
与包内路径须按固定规则对应；清单不能指定任意主机路径、环境变量或执行命令。

成功通过包结构检查不等于数据库可用、密钥配对正确或完整可恢复。这些结论必须
分别验证，缺少环境依赖或尚未执行隔离恢复时应明确显示未验证，不能输出统一的
“恢复就绪”。包内 SHA-256 能检查字节一致性，但攻击者可以重算摘要，不能据此
证明来源或防篡改；后续加密封装还必须验证认证信息。只读校验不会把官方旧 ZIP
自动转换为本项目备份，也不会因识别到数据库文件就触发迁移。

当前 v1 校验已检查真实大小、文件数、摘要和路径，拒绝目录穿越、重复路径、链接、
特殊文件及不支持的版本。数据库完整性/外键和密钥配对仍未实现；恢复前必须补齐。
将来的临时解包必须位于明确拥有的私有目录，不能先覆盖旧文件再发现错误。

恢复旧数据库可能恢复已撤销的登录会话，也可能重新出现通知、证书或 Agent 待办。
正式灾难恢复的默认策略应注销旧网页会话，并让出站任务先进入隔离待确认状态；
具体哪些身份和任务可保留须在实现前写入恢复合同并逐项验证。现有镜像烟测中
保留原会话的冷复制是数据保真检查，不是灾难恢复安全策略已经完成的证据。

仅断网或暂停命令发送不够。证书启动恢复会读取旧 HTTP-01 webroot 的绝对路径，
在原目录身份仍匹配时清理 challenge 文件；访问同步任务还会推进用户、凭据和节点
删除流程。恢复隔离必须在这些任务启动前生效，并覆盖本地文件操作与后台数据变更。
旧 webroot 记录应先隔离，再由操作者重新绑定；不能让恢复包自动取得旧主机目录的
清理权限。

只有在隔离新实例中核对数据库、密钥、用户、订阅、证书和任务状态后，才能由
操作者切换访问或允许远端重新连接。备份功能不自动修改生产反向代理或接管 Agent。

## 发布门槛

- 管理员身份、Origin/CSRF、禁止缓存及固定安全错误；匿名和订阅用户不能创建或下载。
- 并发写入时的快照一致性；活跃任务、读写超时、中断、磁盘满和损坏库的失败处理。
- 缺失/错误密钥、篡改清单、恶意归档和不支持版本均在接触目标数据前拒绝。
- 恢复时验证旧会话、待执行任务和远端身份策略；未确认前不发生实际外发。
- 整套原数据与环境依赖可在新的空卷恢复；旧实例和此前备份不被修改。
- 中文真实浏览器、完整相关回归、精确 Git 镜像和 CI；均在指定 VPS 隔离验收。

已落地的格式代码不包含 Web 接口、认证加密、停写协调或恢复策略，上述剩余门槛
仍需实现和验证，不能由格式层的通过结果替代。
