# 用户续费与管理员审核

用户在“用户中心 → 申请续费”提交申请，管理员在“续费审核”中通过或拒绝。无需配置 Telegram 机器人，也不需要许可证。

这是一条人工审核流程，不接支付平台，不发起扣款，也不会把用户填写的口令视为付款凭证。管理员必须先通过自己的渠道核对付款或其他续费条件。

## 用户操作

1. 登录用户中心，点击“申请续费”。页面显示当前套餐、续费天数、到期时间和申请记录。
2. 填写本次续费口令。口令为 1–256 个字符，不能含换行或控制字符。请自行记录，并通过双方约定的渠道提供给管理员；不要使用登录密码、支付密码或银行卡信息。
3. 提交后等待审核。同一用户只能有一笔待审核申请，提交本身不会延长套餐。
4. 需要取消时，在待审核记录中点击“撤回申请”并确认。已通过或已拒绝的申请不能撤回。

系统仅保存带盐的 Argon2 口令校验值，不保存可读取的口令原文。申请处理或撤回后，校验值也会清除。忘记口令时，应撤回待审申请后重新提交，不能从后台找回原文。

若提交后网络中断，页面保留原申请编号，使用“查询原申请”确认结果，不会自动重新提交。关闭页面后可重新进入申请记录查看；口令不会写入浏览器本地存储。

## 管理员操作

1. 打开“续费审核”，默认显示待审申请，也可以筛选全部、已通过、已拒绝和已撤回记录。
2. 核对用户名、套餐和申请时冻结的续费天数。
3. 批准时，输入用户提供的同一续费口令，并勾选人工核对确认框，然后点击“确认通过并延期”。拒绝无需口令，但同样需要明确确认。
4. 批准回执显示新的到期时间。套餐需要同步到 Agent 时，相关命令进入现有持久队列；请到“访问管理”查看实际执行结果。审批成功不等于离线 Agent 已经完成同步。

新的到期时间以以下三者中最晚的时间为起点，再加上申请时冻结的续费天数：审批时的当前时间、用户当前到期时间、申请时记录的到期时间。尚未到期的剩余时间不会丢失，已经到期的套餐从审批时重新计时。修改套餐的周期不会改写已提交申请的天数。

重复批准同一申请只返回原来的结果，不会再次延期，也不重复创建 Agent 命令。已处理申请不能改成相反结果。申请、套餐延期和访问同步命令在同一数据库事务中提交；配置冲突时全部回滚，申请保留待审状态，修正配置后可再审核。

## 保留与限制

- 只续当前套餐，包括仍保留在账户上的已过期套餐。无套餐、停用或正在删除的用户不能获得续费。提交后如果管理员更换了用户套餐，原申请不会自动把用户切回旧套餐，应先拒绝或撤回后重新申请。
- 只延长时间，不清空流量、不改重置规则、不取消限速或连接限制。已经超额的用户可能仍不可用，直到按原规则重置或由管理员另行处理。
- 不接受用户自选套餐、天数或用户名，用户只能读取、提交和撤回自己的申请。用户会话不能审核续费，管理员会话也不能冒充用户提交申请。
- 每个用户每天最多新建 20 笔申请；提交、撤回和审核另有短时限流。记录分页展示，重启后仍保留。
- 暂未接入 Telegram 续费消息、Bot 按钮、Mini App、自动收款、自动续费或退款。现有套餐临期提醒仍是独立功能。

## 官方依据与实现差异

参考固定版 `tajiaoyezi/miaomiaowuX`：

- [续费申请存储与单次认领](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/storage/renewal_requests.go)
- [审批、延期与套餐下发](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/handler/user_renewal.go)

官方版本要求用户绑定 Telegram，并由运行中的 Bot 发送审批通知。本实现先提供独立的中文网页审核：保留单笔待审、周期快照和幂等审批规则，口令改为仅保存校验值，管理员通过用户提供的口令核对。套餐与审批一次提交，不会留下“已认领但尚未延期”的中间状态。保留现有重置策略，不自动启用月度重置，也不接管付款流程。
