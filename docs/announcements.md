# Web 公告

管理员可以在“系统设置 → Web 公告”发布纯文本公告。公告显示在用户中心，仅有生效
套餐的用户能够读取。这个功能参考官方实例公告流程实现，不依赖 Telegram Bot 或
Mini App。

## 发布和删除

发布时需要选择类型、填写正文，并明确确认内容将向用户显示。标题可以留空，系统会
按类型生成“公告”“系统维护”或“订阅更新”。管理页提供四种有效期：永不过期、
1 小时、1 天和 7 天。接口接受的最长有效期为一年。

发布成功后，公告立即进入生效列表。到期公告会在后续读取时自动隐藏；记录仍留在
数据库中，不会因到期自动删除。管理员也可以手动删除，删除成功后用户中心不再显示。
当前管理页只列出生效公告，最多返回最近 100 条。

网络中断或回执异常时，页面不能判断写操作是否已经提交。它会重新读取公告，但不会
自动重发发布或删除请求。操作者应核对当前列表，再决定是否继续。

## 用户可见范围

用户必须同时满足以下条件：

- 已登录独立的用户账户；
- 账户处于启用状态；
- 已分配当前套餐；
- 套餐尚未到期。

没有套餐或套餐已到期时，接口返回空列表；停用、待删除或不存在的账户不能通过用户
认证读取公告。流量已用完不会单独隐藏公告，因为公告资格按当前套餐是否生效判断。
公告读取失败不会阻止用户查看套餐、
订阅链接和其他账户功能，页面只显示一条固定警告。

标题和正文始终按纯文本渲染。正文保留换行和制表符，不解析 HTML、Markdown、链接或
脚本；标题最多 100 个字符，正文最多 2000 个字符。不要在公告中填写密码、Token、
私有订阅地址或其他秘密。

当前没有“已读”“未读”、逐用户隐藏或持久关闭协议。页面每次读取都会显示仍生效的
公告。这与固定官方后端的实例公告模型一致，没有额外发明客户端已读状态。

## 权限、存储和接口

管理接口要求管理员会话，发布和删除还要通过现有 Origin/CSRF 校验，并按管理员限制
为每分钟 30 次。请求只接受 UTF-8 JSON；发布体最多 16 KiB，拒绝未知字段、重复
字段、非有限数字和非法控制字符。响应禁止缓存，错误只返回固定代码，不回显正文或
服务器异常。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/announcements` | 管理员读取当前生效公告 |
| `POST /api/v1/announcements` | 发布公告 |
| `DELETE /api/v1/announcements/{id}` | 删除一条公告 |
| `GET /api/v1/account/announcements` | 登录用户读取对自己生效的公告 |

公告存放在所选 SQLite 或 PostgreSQL 数据库的独立 `web_announcements` 表中，随正常
数据库快照和备份一起保存，不新增密钥。

## 与官方实现的边界

行为依据是固定官方源码中的
[announcement.go](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/handler/announcement.go)
和[公告存储](https://github.com/tajiaoyezi/miaomiaowuX/blob/c12ce653bc07fe30426b7dfcb85076974b7be0e0/internal/storage/announcement.go)。
本期实现管理员实例公告、有效期、删除和有套餐用户读取。

官方的逐类型模板/通道配置、探测源设置、Bot/Mini App 投递、用户 Telegram 绑定，
以及服务器阻断时自动生成并广播节点公告不在当前范围内。因为自动节点公告未实现，
本期也没有暴露节点定向字段；这不影响普通 Web 公告的发布、到期和删除。
