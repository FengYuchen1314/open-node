# 动态 DNS

Open Node 可以在 Agent 上报的公网地址变化后，自动更新服务器域名的 A/AAAA 记录。
功能完全免费，复用“证书管理”中已经加密保存的 DNS 服务商凭据，不需要另存一份密钥。

## 使用方法

1. 先到“证书管理”添加 DNS 服务商并确认凭据有目标域名的记录读写权限。
2. 确认服务器 Agent 已连接并上报公网 IPv4 或 IPv6。
3. 打开“动态 DNS”，为服务器选择显式服务商或“自动选择”，填写 IPv4 域名和可选的
   IPv6 域名，然后启用。
4. 保存后后台会执行首次同步。也可以点击“同步”排队一次手动检查；页面会显示同步中、
   最近成功时间或固定的失败原因。

支持 Cloudflare、阿里云 DNS、腾讯云 DNSPod v3、DNSPod Token、GoDaddy 和 NameSilo。
证书页的 HTTP webhook 服务商不能用于 DDNS。自动模式先查找覆盖目标域名且绑定了 DNS
服务商的托管证书；没有匹配时，再对已配置服务商逐一做只读域名管辖探测。

IPv4 写入 `pull_address` 的 A 记录。IPv6 写入 `pull_address_v6` 的 AAAA 记录；后者留空
时沿用 IPv4 域名，形成同域名双栈。某一地址尚未上报时不会删除 DNS 上的既有记录；两种
公网地址都不可用会记录失败。关闭 DDNS 只停止后续更新，也不会删除记录。

DDNS 域名同时是该服务器的对外拉取/节点地址。修改前请确认新记录、证书和客户端连接
方式一致。接入的联邦服务器目前属于独立工作区，不能在本页配置 DDNS。

## 执行与恢复

后台以数据库中的“上次成功 IP”对比当前 Agent IP，因此注册、心跳或重启后发现漂移都会
排队更新，不依赖一次性的内存事件。每次更新有 75 秒数据库租约和修订号栅栏：进程异常
退出后租约可恢复，旧配置的迟到结果不能覆盖新配置。失败后每五分钟自动重试；手动同步
可提前触发。A/AAAA 更新使用 upsert，不会因为记录已存在而重复创建。

DNS 凭据仍由证书密钥库加密，DDNS API 和状态不会返回明文。供应商请求只发往代码固定的
官方 HTTPS 端点，15 秒超时，响应最多读取 256 KiB，远端错误正文不会进入 Web 响应。
备份时必须把 SQLite 和证书密钥目录一起保存；丢失证书密钥后，DDNS 也无法解密凭据。

## 与固定官方实现的关系

本批参考 `miaomiaowuX` 固定提交
`c12ce653bc07fe30426b7dfcb85076974b7be0e0` 的 `internal/ddns/`、
`ddns_admin.go`、Agent 连接触发和服务器 DDNS 存储字段。六类供应商、A/AAAA、显式/自动
服务商、手动触发、状态和失败重试语义一致。Open Node 用耐久租约和持久 IP 对比替代官方
进程内互斥锁与五分钟 reconciler，适合现有的可恢复 worker/备份协调边界。

专项测试使用固定的模拟供应商响应，已经覆盖请求签名/路由边界、域名公共后缀切分、凭据
不回显、漂移、租约、修订冲突和重试状态；没有使用操作者的真实 Cloudflare、阿里云、
腾讯云、DNSPod、GoDaddy 或 NameSilo 账号写公网记录。各供应商的账号资格、API 权限、
额度和区域限制仍需部署者用自己的域名验收。
